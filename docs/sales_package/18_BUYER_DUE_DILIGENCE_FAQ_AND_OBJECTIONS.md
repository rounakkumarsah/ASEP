## 1. Architectural & Engineering Questions

### Q1: How does ASEP ensure agents do not get stuck in infinite execution loops?
**Answer:**  
ASEP rejects unconstrained ReAct loops in favor of a **deterministic LangGraph StateGraph DAG** (`backend/src/runtime/graph.py` and `backend/src/agents/supervisor.py`). Every plan generated by the Planner is decomposed into a maximum of 10 discrete steps with explicit transition conditions. If a step fails, the circuit breaker pattern (`backend/src/production/reliability.py`) triggers a retry policy (exponential backoff up to 3 attempts), after which it either routes to a replanning node or pauses for Human-in-the-Loop intervention.

### Q2: How does ASEP prevent container breakout or malicious host execution?
**Answer:**  
All execution happens within hardened Docker sandboxes (`backend/src/tools/impl.py`). The runtime enforces:
1. Non-root user execution (`user="1000:1000"`).
2. Dropping all Linux kernel capabilities (`cap_drop=["ALL"]`).
3. Disabling privilege escalation (`security_opt=["no-new-privileges:true"]`).
4. Read-only root filesystem with dedicated non-executable `tmpfs` mounts.
5. Strict process limits (`pids_limit=100`) and memory/CPU limits (512MB RAM, 1 CPU).

### Q3: What is the 4-Tier Hybrid Memory Architecture, and why is it superior to simple vector RAG?
**Answer:**  
Single-layer vector databases suffer from semantic drift, lack of chronological awareness, and inability to understand hierarchical code syntax. ASEP combines four purpose-built layers:
* **Tier 1 (Working Memory):** High-speed Redis cache for in-flight transaction state and prompt context.
* **Tier 2 (Episodic Memory):** PostgreSQL event timeline scored with exponential time-decay fusion ($Score = Similarity \times e^{-\lambda \Delta t}$).
* **Tier 3 (Semantic Memory):** Qdrant dense vector store for semantic code search across document chunks.
* **Tier 4 (Procedural Memory):** Neo4j knowledge graph mapping Abstract Syntax Trees (AST), functions, classes, imports, and cross-file dependencies.

## 2. Security, Compliance & License Diligence

### Q4: Are there any AGPL or viral copyleft license risks in the codebase?
**Answer:**  
The entire platform is 100% MIT-licensed with permissive dependencies (MIT, Apache-2.0, BSD-3). One optional PDF parsing utility (`pymupdf` v1.28.0) carries an AGPL-3.0 license. For buyers wishing to distribute a 100% proprietary closed-source binary, ASEP includes a documented 1-line configuration to use `pypdf` (MIT) or `pdfplumber` (MIT) without any architectural changes (`docs/sales_package/16_DEPENDENCY_LICENSE_AUDIT.md`).

### Q5: How was the Next.js 15.1.0 authorization bypass vulnerability (GHSA-gp8f-8m3g-qvj9) resolved?
**Answer:**  
The frontend was upgraded to `next@15.5.23` and `eslint-config-next@15.5.23`. Full regression testing (`tsc --noEmit`, `next lint`, and production build) verified that all middleware authorization bypass and App Router security advisories are fully patched with 0 vulnerabilities in direct dependencies.

### Q6: How is multi-tenancy enforced in the database?
**Answer:**  
ASEP enforces **PostgreSQL Row-Level Security (RLS)** directly at the database engine level (Alembic migration `37c46316c0a8_enable_rls_multi_tenancy.py`). Even if application-level tenant filters are bypassed, PostgreSQL enforces `app.current_tenant` isolation on `projects` and `agent_runs` tables, guaranteeing tenant data isolation.

## 3. Commercial & Integration Diligence

### Q7: Can an enterprise run ASEP completely air-gapped without OpenAI or Anthropic API keys?
**Answer:**  
Yes. ASEP is natively model-neutral and includes first-class support for local LLM backends (Ollama, vLLM, LM Studio) via `src/ai_runtime/providers/ollama.py`. The entire agent graph, memory retrieval, and execution engine can run inside a secure VPC or on-premise Kubernetes cluster with zero external internet access.

### Q8: How easy is it to white-label or rebrand the frontend?
**Answer:**  
The frontend is built on Next.js 15.5.23 with Tailwind CSS and Radix UI primitives. All brand tokens (colors, logos, typography, product names) are centralized in `frontend/src/app/globals.css` and `frontend/tailwind.config.ts`. Rebranding can be completed in under 4 hours.
